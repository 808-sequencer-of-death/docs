This page tracks two things: changes FedRAMP makes to the Consolidated Rules for 2026, and changes to this site. Each upstream entry summarizes FedRAMP's own [changelog](https://www.fedramp.gov/2026/changelog/) and links the official rules and our summaries. The official changelog governs if anything here differs. Each entry starts with its date. For an upstream release, that's the date FedRAMP published it.

<Update label="2026-11-07" description="Upstream 2026.11.02.01">
  **Date:** 2026-11-07

  - **Rules:** no upstream rule text changed since release `2026.11.02.01`. See the official [changelog](https://www.fedramp.gov/2026/changelog/). One staff position was added to [FedRAMP certification](/rules/fedramp-certification): a Rev5 Class C to Class D uplift is a new certification that needs a fresh independent assessment and package ([`FRC-APP-FIA`](https://www.fedramp.gov/2026/reference/fedramp-certification/#fresh-independent-assessment), [`FRC-APP-FCP`](https://www.fedramp.gov/2026/reference/fedramp-certification/#fresh-fedramp-certification-package)).
  - **Discussions:** see [Rev5 CR26 questions](/discussions/rev5-cr26-questions), [20x CR26 questions](/discussions/20x-cr26-questions), [Notable staff answers](/discussions/notable-staff-answers) and [RFC history](/discussions/rfc-history).
    - [#146](https://github.com/FedRAMP/community/discussions/146): `pete-gov` said an uplift needs a fresh assessment and package, and is realistic only with an agency sponsor ([comment](https://github.com/FedRAMP/community/discussions/146#discussioncomment-19443693)). `pete-gov` also said emergency tests go only to certified providers, and uncertified providers who plan to apply must still have the `VDR` and `VER` materials ready ([comment](https://github.com/FedRAMP/community/discussions/146#discussioncomment-19445043)). A new question on assessor write-ups and the SDR schema is unanswered.
    - [#147](https://github.com/FedRAMP/community/discussions/147): `pete-gov` said whether plaintext east-west traffic is "otherwise secured" under `KSI-SVC-SIN` is a technical decision for your security engineer ([comment](https://github.com/FedRAMP/community/discussions/147#discussioncomment-19448017)).
    - [#189](https://github.com/FedRAMP/community/discussions/189): `pete-gov` gave illustrative, non-binding answers on reusable EC2 AMIs under `VDR` and `VER` ([comment](https://github.com/FedRAMP/community/discussions/189#discussioncomment-19444953)).
    - [#193](https://github.com/FedRAMP/community/discussions/193): `pete-gov` said the core force of a rule governs when five rules carry a second keyword ([comment](https://github.com/FedRAMP/community/discussions/193#discussioncomment-19446546)).
    - [#192](https://github.com/FedRAMP/community/discussions/192): typos in `SCN-FRP-CAP`, `FRD-IIR` and `SCN-CSO-EVA` will be fixed in the next version, tracked in [FedRAMP/rules#53](https://github.com/FedRAMP/rules/issues/53).
    - [#179](https://github.com/FedRAMP/community/discussions/179) (RFC-0035): one new community comment. It isn't a staff position.
</Update>

<Update label="2026-11-03" description="Upstream 2026.11.02.01">
  **Date:** 2026-11-03

  - **Rules:** FedRAMP published release `2026.11.02.01` on 2026-11-02 and said it will move to a monthly release cadence, typically in the first week of each month. See the official [changelog](https://www.fedramp.gov/2026/changelog/). Changes that matter to you:
    - [`FRC-CLA-MFR`](https://www.fedramp.gov/2026/reference/fedramp-certification/#mandatory-fedramp-rules-for-class-a) now also makes `SDR-CSX-KSI` mandatory for Class A. [`FRC-CLA-RFR`](https://www.fedramp.gov/2026/reference/fedramp-certification/#recommended-fedramp-rules-for-class-a) no longer lists `CPO-CSF-CPM`.
    - [`FRC-CCL-UCC`](https://www.fedramp.gov/2026/reference/fedramp-certification/#upgrading-certification-class): upgrading is obtaining a new FedRAMP Certification, so the obtain deadlines in each ruleset apply. FedRAMP may make case-by-case exceptions. `FRC-CCL-DCC` got a typo fix in its note only.
    - [`FRD-MAS`](https://www.fedramp.gov/2026/definitions/#minimum-assessment-scope): new definition of Minimum Assessment Scope.
    - `IEC-CSO-IIR`, `IEC-CSO-OIR` and `IEC-CSO-FIR`: the update to all necessary parties is marked optional in notification metadata. FedRAMP notes the `updated` array wasn't updated.
    - [`MKT-CSO-PML`](https://www.fedramp.gov/2026/reference/marketplace-listing/#provider-marketplace-listing-requests): corrected form name. [`KSI-SCR-MIT`](https://www.fedramp.gov/2026/reference/key-security-indicators/#mitigating-supply-chain-risk): wording reordered with no material impact.
    - Pages updated: [FedRAMP certification](/rules/fedramp-certification), [Minimum assessment scope](/rules/minimum-assessment-scope), [Incident evaluation and communication](/rules/incident-evaluation-and-communication), [Marketplace listing](/rules/marketplace-listing), [Key security indicators](/rules/key-security-indicators).
  - **Discussions:** [#146](https://github.com/FedRAMP/community/discussions/146) has a new staff position from `pete-gov` on 2026-11-03 about vulnerabilities under a coordinated disclosure embargo ([comment](https://github.com/FedRAMP/community/discussions/146#discussioncomment-19372816)) and a new unanswered question about `IVV-IAS-VEF`. See [Rev5 CR26 questions](/discussions/rev5-cr26-questions). In the RFC threads ([#179](https://github.com/FedRAMP/community/discussions/179), [#180](https://github.com/FedRAMP/community/discussions/180), [#181](https://github.com/FedRAMP/community/discussions/181)), `pete-gov` explained that proposed `CMU-CSO-TSC` covers replacing CMVP-validated modules with non-validated ones, not patching ([comment](https://github.com/FedRAMP/community/discussions/181#discussioncomment-19359887)). Other new comments are community context. See [RFC history](/discussions/rfc-history).
</Update>

<Update label="2026-10-08" description="Upstream 2026.10.08.01">

</Update>

<Update label="2026-10-05" description="Upstream 2026.10.05.01">
  **Date:** 2026-10-05

  - **Rules:** clarifications to seven rules. FedRAMP now tracks rule improvements as [issues in the FedRAMP Rules repository](https://github.com/FedRAMP/rules/issues).
    - [`VER-EVA-EPA`](https://www.fedramp.gov/2026/reference/vulnerability-evaluation-and-reporting/#estimate-potential-agency-impact) (Estimate Potential Agency Impact): added PAIN N0 for vulnerabilities whose exploitation is extremely unlikely to have any adverse effect on agencies. See [Vulnerability evaluation and reporting](/rules/vulnerability-evaluation-and-reporting).
    - [`FRC-CSO-JSN`](https://www.fedramp.gov/2026/reference/fedramp-certification/#fedramp-json-schemas) (FedRAMP JSON Schemas): public JSON MUST work with modern web frameworks, including CORS access from other domains and headers such as `Content-Type: application/json`. See [FedRAMP certification](/rules/fedramp-certification).
    - [`CDS-CSO-PUB`](https://www.fedramp.gov/2026/reference/certification-data-sharing/#public-information) (Public Information): the logo link must be a valid, properly named image that displays in a browser without processing. See [Certification data sharing](/rules/certification-data-sharing).
    - [`CMU-CSO-UVM`](https://www.fedramp.gov/2026/reference/cryptographic-module-use/#using-validated-cryptographic-modules) (Using Validated Cryptographic Modules): added a note that new algorithms added in a module's update stream aren't covered as validated. See [Cryptographic module use](/rules/cryptographic-module-use).
    - [`MKT-CAS-LRQ`](https://www.fedramp.gov/2026/reference/marketplace-listing/#listing-requests-for-advisors) and [`MKT-IAS-LRQ`](https://www.fedramp.gov/2026/reference/marketplace-listing/#listing-requests-for-assessors): updated the listing form names and URLs. See [Marketplace listing](/rules/marketplace-listing).
    - [`FRC-CSF-RDY`](https://www.fedramp.gov/2026/reference/fedramp-certification/#fedramp-ready-conversion) (FedRAMP Ready Conversion): grammar fix only.
  - **Discussions:** the `FRC-CSO-JSN` change follows FedRAMP staff comments by `pete-gov` on 2026-09-17 in [discussion #175](https://github.com/FedRAMP/community/discussions/175#discussioncomment-18480627), which said FedRAMP planned to make clear that JSON must be directly consumable by web applications.
  - **Content:** adopted new social cards on the official site.
</Update>
