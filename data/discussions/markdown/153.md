# Data-quality findings from a full-coverage conversion of the CR26 consolidated rules (v2026.07.14.01)
Source: https://github.com/FedRAMP/community/discussions/153

## Original post — christoph-puppe, 2026-07-20T19:22:40Z

Hi all 

sharing findings from an experiment I ran in personal capacity. I wrote a converter that maps the complete consolidated rules JSON into an experimental semantic model, with a computed coverage report: every source field path inventoried, every path assigned a declared destination. Result: 7,294 leaf values, 100 % declared coverage, zero unexplained fields. The process surfaced a few things that may be useful to the FedRAMP data team:

1. **Nine undeclared subsets.** `CSX` (in `20x` data blocks) and `CSF` (in `rev5` data blocks) appear under `FRR.*.data.*` for CDS, CPO, FRC, IVV and SDR, but are not declared in the corresponding `info.subsets`. Tooling that builds applicability scopes from `info.subsets` will silently miss these rules.
2. **Layered rule counts.** The corpus contains 246 rules = 225 track-independent (`data.all`) + 12 rev5-only + 9 20x-only. Worth documenting, since naive parsers that read only `data.all` will report 225.
3. **29 variant-only rules** exist solely inside `varies_by_class` with no base `statement`/`force` — consumers need a defined interpretation for the base case.
4. **Consistency compliment:** across all 111 class-variant `force` changes, there is not a single easing — every published class delta tightens or specifies. That's a remarkably clean dataset property.
5. **FRD quality:** all 264 term references from rules and KSIs resolve against the FRD via term + `alts` matching — the alias lists demonstrably earn their keep. The 51 variant timeframes without a base timeframe and the 79 CTL overlay entries are documented in the report as well.
6. The 373 KSI→800-53 control links import cleanly as typed, provenance-carrying mapping objects.

The converter script and the full coverage report (JSON: every path → destination, with counts) are available. The wider experiment — a semantic-core architecture hypothesis derived from measuring three national corpora (ISM, BSI IT-Grundschutz++, CR26), with a handbook and worked examples packaged as an AI skill — is here: [Semantic OSCAL Ideas](https://github.com/christoph-puppe/Semantic-OSCAL-2-Ideas). Criticism of the architecture itself is explicitly welcome; happy to file any of the data findings above as separate issues if useful.

A summary can be found on [LinkedIn](https://www.linkedin.com/posts/christophpuppe_oscal-complianceascode-itgrundschutz-ugcPost-7484537947745226754-RTbA/)

— Christoph Puppe (personal capacity)

## pete-gov (FedRAMP) — [2026-07-20T19:41:14Z](https://github.com/FedRAMP/community/discussions/153#discussioncomment-17705910)

> 1. **Nine undeclared subsets.** `CSX` (in `20x` data blocks) and `CSF` (in `rev5` data blocks) appear under `FRR.*.data.*` for CDS, CPO, FRC, IVV and SDR, but are not declared in the corresponding `info.subsets`. Tooling that builds applicability scopes from `info.subsets` will silently miss these rules.

For this one I'm hoping it's a structural misunderstanding - subsets are declared in `info.subsets` if they apply to both Rev5 and 20x. If a subset applies only to one of those, then it is declared in `info.20x.subsets` or `info.rev5.subsets` instead.

For example, `CSF` is a Rev5-only subset so it is declared in `info.rev5.subsets`. `CSX` is a 20x-only subset so it is declared in `info.20x.subsets`.

> 3. 29 variant-only rules exist solely inside varies_by_class ...

Yep, this is explicit in the schema, there either needs to be a `statement`/etc. OR there needs to be a `varies_by_class` with the `statement`/etc.

Similar to the structure for (1) above - things apply globally by default, but in some cases there are specific applications and those are then defined on their own.

Cheers!
