# Authorization Data Sharing Standard, FedRAMP Definitions, and other FRMR updates on 8/25
Source: https://github.com/FedRAMP/community/discussions/79

## Original post — pete-gov (FedRAMP), 2025-08-25T17:03:27Z

On August 25, a number of updated materials were published on the [FedRAMP 20x Machine-Readable (FRMR) Docs repository](https://github.com/FedRAMP/docs/), including:

## Non-breaking changes to all 20x documentation

- All human-readable materials now have a Documentation Guidelines section that clarifies the requirements keywords
- Definition sections were removed from individual documents
- Use of defined terms in all materials were italicized
- `referenced_fr` sections for rules that included definitions were updated to include the correct target definition in `FRR-FRD-ALL` for the definitions wherever possible
- Most of these changes were done via simple scripting and manual work so there may be gaps
- Versions and descriptions were updated

**There should not be any material changes the previous existing documentation. Any such changes, especially to KSIs, is accidentally and should be reported to pete@fedramp.gov or on this thread ASAP.**

## Consolidated FedRAMP Definitions

Managing separate FedRAMP definitions in each standard is starting to get a bit confusing and awkward - plus RFC-0012 feedback made it clear many people fail to reference definitions scattered across standards. To simplify this moving forward and be more consistent, FedRAMP will maintain a single FedRAMP Definitions set of FedRAMP Rules called `FRR-FRD-ALL` which will contain any finalized definitions after public comment.

It is available in the following formats: [Markdown](https://github.com/FedRAMP/docs/blob/main/markdown/FRMR.FRD.fedramp-definitions.md) // [PDF](https://github.com/FedRAMP/docs/blob/main/pdf/FRMR.FRD.fedramp-definitions.pdf) // [JSON](https://github.com/FedRAMP/docs/blob/main/FRMR.FRD.fedramp-definitions.json)

- All finalized definitions in all existing standards were moved to this consolidated document
- Definitions in this document should be referenced as needed

## Authorization Data Sharing Standard

The Authorization Data Sharing Standard for FedRAMP 20x (pending for Rev5) was released today. All FedRAMP 20x Phase One pilot participants will be expected to meet the requirements in this standard within one year of receiving a pilot authorization and must demonstrate quarterly progress towards implementation. This standard will likely be **required** for 20x Phase Two pilot participants.

It is available in the following formats: [Markdown](https://github.com/FedRAMP/docs/blob/main/markdown/FRMR.ADS.authorization-data-sharing.md) // [PDF](https://github.com/FedRAMP/docs/blob/main/pdf/FRMR.ADS.authorization-data-sharing.pdf) // [JSON](https://github.com/FedRAMP/docs/blob/main/FRMR.ADS.authorization-data-sharing.json)

- This standard builds on feedback from RFC-0011 
- It has been simplified in many ways to realign with FedRAMP's philosophy of testing and evaluating with early adopters
- This standard will be applied to Rev5 via a Balance Improvement Release, and interested participants should follow the Rev5 working group for next steps. **Rev5 providers MUST NOT adopt this standard without participating in a Beta Test.**
- Participants in the 20x Phase One pilot should follow this standard and prepare to adopt it, but adoption is **not** required to obtain a pilot authorization
