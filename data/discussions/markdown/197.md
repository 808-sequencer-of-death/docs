# Too Big to De-Certify?
Source: https://github.com/FedRAMP/community/discussions/197

## Original post — LPT00-ctrl, 2026-11-10T23:46:14Z

What happens when a cloud with numerous authorizations becomes insecure? Can it become too big to de-certify? How will the FedRAMP PMO be able to de-certify a cloud with 50-100 authorizations if it becomes insecure? 

## pete-gov (FedRAMP) — [2026-11-11T19:03:30Z](https://github.com/FedRAMP/community/discussions/197#discussioncomment-19549221)

> What happens when a cloud with numerous authorizations becomes insecure? Can it become too big to de-certify? How will the FedRAMP PMO be able to de-certify a cloud with 50-100 authorizations if it becomes insecure?

The important thing in a situation like that wouldn't be whether or not the service has a FedRAMP Certification, it would be the massive risk of federal government agencies using it. In the event that FedRAMP itself believes a cloud service used by 50-100 agencies is a risk, we would work with the FedRAMP Board and CISA to initiate a red team assessment of that service. If the risk was more tangible, FR would report the issues to the FedRAMP Board, OMB, CISA, DOJ, ONCD, and the CIO Council as appropriate... but it is usually one of the national security or law enforcement agencies that first identify insecure behaviors because they are related to fraud/etc. and they come to FR with that information.

If a cloud service with 50-100 authorizations to operate government-wide made security decisions that led to it being too insecure to use, we can pretty much guarantee that CISA would release an Emergency Directive banning its use by federal agencies or the Federal Acquisition Security Council would order its removal from federal information systems (similar to how [they recently did for Acronis](https://www.federalregister.gov/documents/2026/10/30/2026-22215/notice-of-order-regarding-exclusion-and-removal-of-acronis-products-from-federal-civilian-executive)). FedRAMP would de-certify such services as directed.
