# Machine Readable (FRMR) docs // discussions and updates
Source: https://github.com/FedRAMP/community/discussions/50

## Original post — pete-gov (FedRAMP), 2025-06-28T15:36:55Z

FedRAMP intends to fully support machine-readable documentation for rules and requirements related to 20x. Our initial work is available publicly in the following GitHub repository:

https://github.com/FedRAMP/docs/

We have disabled collaboration on that repository for now to limit confusion so I'm creating a thread here for discussion, updates, etc. We're currently using the underlying JSON data to generate markdown and PDF documents and intend to release all future 20x docs in this format.

Feedback, suggestions, forks, conversions, etc. are deeply welcome!

---

### Updates

- **2025-06-28**: v.0.2.0 has been released with updates to Key Security Indicators (25.05C)

  - Mappings to SP 800-53 controls have been added to the KSI JSON
  - These updates _should not_ have materially changed the KSIs, we did quite a bit of automated and manual double checking but if you notice something please let me know.
  - Human readable versions with controls are available separately now (the default will not include the reference mappings)
    - https://github.com/FedRAMP/docs/blob/main/markdown/FRMR.KSI.key-security-indicators-with-controls.md
    - https://github.com/FedRAMP/docs/blob/main/pdf/FRMR.KSI.key-security-indicators-with-controls.pdf

## jimFortreum — [2025-07-10T18:07:13Z](https://github.com/FedRAMP/community/discussions/50#discussioncomment-13723835)

We need to start thinking less about machine-readable formats in the age of AI and more about self-describing metadata standards.  With AI, near real-time format translation is available today, converting files on the fly based on users' or system input needs.  Structured formats still ensure interoperability across systems but are now less about what formats/applications are required and more about telling an AI system to summarize the document.   CSPs can provide their RAR and SAR descriptions in JSON, but once shared, one can process the file using AI to rephrase the text and give a human-readable format.  As file extensions and data evolve to carry self-describing metadata (like JSON), file extensions will fall away. Concentrating on the self-describing metadata standards like OSCAL or whatever standard emerges is more important than a file being in a machine-readable format.   Modifying OSCAL/some standard for KSIs for 20xP1/P2 will support faster automation of security assessments than just requesting machine-readable formats, because all formats are machine-readable, right.     CSPs can upload data to AI systems and tell it to convert the data into OSCAL format as a JSON file.   It comes down to what self-describing metadata the 20xP1 program desires, because I have AI to convert that data into whatever format is desired.
