## In short

Across the 245 rules in the Consolidated Rules, **72 rules make a provider produce something**: a document, report, dataset, published web data, form or notification with required content. Another 14 rules set deliverables for assessors, advisors, agencies and FedRAMP.

- 61 of the 72 provider deliverables are MUST in at least one class.
- 19 of them name a FedRAMP JSON schema. When a rule names a schema, your JSON MUST validate against it, and public JSON MUST work with standard web applications ([`FRC-CSO-JSN`](https://www.fedramp.gov/2026/reference/fedramp-certification/#fedramp-json-schemas)).
- 24 rules notify someone through a specific channel, such as a FedRAMP form or `fedramp_security@fedramp.gov`. They're listed in [Notification channels](#notification-channels).

## How this list was built

- **Included:** a rule is listed when its statement (or a class-specific statement) requires you to create, supply, publish or maintain a defined output.
- **Force:** a single value means the force is the same for every class. Otherwise each class is listed, for example "A: MAY, B: MUST, C: MUST, D: MUST". Rev5-only rules have no Class A.
- **Deliverable column:** a short summary written for this site. The Rule, Force and Schema columns come straight from the upstream rule text.

### What's not included, and why

- **Process and behavior rules.** Examples: vulnerability detection and response (`VDR-CSO-DET`), vulnerability evaluation (`VER-EVA-ELX`, `VER-EVA-EIR`, `VER-EVA-EPA`), incident evaluation and rating (`IEC-CSO-EFR`, `IEC-CSO-EFI`) and change evaluation (`SCN-CSO-EVA`). The records they produce are captured by the reporting rules listed below.
- **Capability and infrastructure rules.** Examples: the FedRAMP Security Inbox rules (`AFC-CSO-INB`), using a trust center (`CDS-CSO-UTC`) and the configuration comparison, export and API capabilities (`SCG-ENH-CMP`, `SCG-ENH-EXP`, `SCG-ENH-API`).
- **Package maintenance cadence.** `CPO-CSX-CPM` and `CPO-CSF-CPM` set how often you refresh the package, not a new output. See [Certification package overview](/rules/certification-package-overview).
- **Notifications without required content.** `AFC-CSO-NOC`, `CDS-UTC-AAD` and `FRC-CCL-DNP` require you to notify someone but don't specify the content. The first two have a named FedRAMP form, so they appear in [Notification channels](#notification-channels).
- **Schema-tagged activities.** `CDS-CSO-UTC`, `IEC-CSO-EFI` and `SCN-CSO-EVA` name a JSON schema, but the rule is an activity. The schema shows where the result ends up (the package overview, incident reports and change notifications).
- **Judgment calls.** `MAS-CSO-IIR` and `MAS-CSO-FLO` say "identify" and "document", but `CPO-CSO-OVR` pulls both into the package overview, so they're included. `MAS-CSO-MDI` (include metadata in scope) is a scoping rule, so it isn't.
