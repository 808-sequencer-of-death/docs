## What these digests are

FedRAMP staff answer many practical questions about the Consolidated Rules for 2026 (CR26) in the public FedRAMP community discussions on GitHub. Those answers are spread across long threads. These pages pull out what staff said, group it by topic and ruleset, and link each position to the exact comment.

Each digest gives you:

- A short **bottom line** for executives.
- **FedRAMP staff positions**, each paraphrased in a callout with the staff member's GitHub login, the date and a link to the comment.
- **Open questions** that were still unanswered in the thread.
- **What it means for you**, tied to rule IDs, and only what the sources support.

## How staff and community posts are told apart

Only posts marked official in the synced discussion data are treated as FedRAMP positions. The sync script (`scripts/fedramp_discussions_sync.py`) marks a post official when:

- The author's GitHub association with the `FedRAMP/community` repository is **owner**, **member** or **collaborator**.
- Or the author's login is on a configured allowlist, or ends in `-gov`.

Threads that carry the **FedRAMP Official** label are flagged as official threads. Everything else is community comment. We use community comments only to explain what was asked, never as guidance.

<Note>
  The `-gov` login rule can flag accounts that aren't on FedRAMP's published list of responders. For example, `nathan-gov` is marked official in the data but isn't on the staff list in the Rev5 thread, and only asked questions. The digests point out cases like this.
</Note>

## Staff statements don't override the rules

The published rules are the source of truth. A staff post explains how FedRAMP reads a rule, or what it plans to do. It doesn't change the rule.

- If a staff post conflicts with the current rule text, the [official rules](https://www.fedramp.gov/2026/) govern, and the digest says so.
- If a later upstream release adopted what staff said, or replaced it, the digest notes the release and links the current rule.
- An RFC is a proposal. It isn't a requirement, even while it's open.
