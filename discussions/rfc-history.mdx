## What RFCs are

FedRAMP must seek public comment before it publishes guidance that affects stakeholders. Its Request for Comment (RFC) process is how anyone can give formal feedback ([Getting Support](https://www.fedramp.gov/2026/support/); the full list is at [fedramp.gov/rfcs](https://fedramp.gov/rfcs)). Each RFC has a formal comment thread. Many also have a separate Q&A thread, because FedRAMP staff don't answer questions in formal comment threads.

<Warning>
  An RFC is a proposal, not a rule. Staff said a closed RFC is irrelevant once it closes, except for any outcome it links to ([`pete-gov`, 2026-09-02](https://github.com/FedRAMP/community/discussions/147#discussioncomment-18255608)). They have also stressed that RFCs "do not establish any requirements" ([`pete-gov`, 2026-09-23](https://github.com/FedRAMP/community/discussions/172#discussioncomment-18570501)). For current requirements, use the [rules](/rules).
</Warning>

## How to read the table

- **Status** is the thread's GitHub category. **Closed RFC** and **Open RFC** are formal comment threads. **Q&A** marks a "General RFC Discussion" thread. All Q&A threads below are closed except #181.
- **Related ruleset** names a current ruleset only when the RFC's title or text names it directly, or the current rule carries the same name. Otherwise it shows "—". Many RFCs fed into several rulesets, or into pages that aren't rulesets, such as Rev5 control guidance and Scope of FedRAMP.
- **Date** is when the thread was opened.

<Note>
  **RFC-0035 is open.** It proposes changes to the current `CMU` rules, including changing `CMU-CSO-UVM` for Class D from MUST to SHOULD. Until FedRAMP publishes a change upstream, the current [`CMU-CSO-UVM`](https://www.fedramp.gov/2026/reference/cryptographic-module-use/#using-validated-cryptographic-modules) text governs, and Class D is MUST.
</Note>

<Note>
  **RFC-0036 is open.** It proposes new definitions, changes to six rulesets and 10 new Key Security Indicators to test in the 20x Phase 4 cloud-hosted Class D pilot. It adds rules such as `FRC-CLD-PCD`, `FRC-CLD-CCH` and `FRC-FRA-FOD`. None of this is in the published rules. In [#181](https://github.com/FedRAMP/community/discussions/181), `pete-gov` said it applies to 20x only and wouldn't apply to Rev5 ([comment](https://github.com/FedRAMP/community/discussions/181#discussioncomment-19081418)). FedRAMP doesn't answer questions in the RFC threads themselves.
</Note>
